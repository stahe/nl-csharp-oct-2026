    5. Veelgebruikte .NET-klassen

    Hier presenteren we een aantal veelgebruikte klassen van het .NET-platform: tekenreeksen, arrays, collecties, bestanden en reguliere expressies. Ook behandelen we LINQ (Language Integrated Query), dat in de cursus van 2008 werd weggelaten, hoewel het al beschikbaar was sinds C# 3: het is nu de meest gebruikelijke manier om collecties in C# te bewerken. Eerst laten we zien hoe u informatie kunt vinden over de duizenden beschikbare klassen. Deze handleiding is onmisbaar voor elke C#-ontwikkelaar, ook voor ervaren ontwikkelaars.

    De voorbeelden in dit hoofdstuk, met uitzondering van de voorbeeldapplicatie aan het einde, zijn toepassingen met één bestand die worden uitgevoerd met [dotnet run file.cs]. Ze staan in de map [05-classes-dotnet] van de cursuscode en draaien in de Franse locale (fr-FR), behalve de voorbeelden met LINQ en reguliere expressies, die in de Amerikaans-Engelse locale (en-US) draaien.

    5.1. Hulp zoeken bij .NET-klassen

    In de cursus van 2008 werd de MSDN-help die met Visual Studio 2008 werd geïnstalleerd uitgebreid beschreven, met schermafbeeldingen. Deze lokale help is niet meer beschikbaar: de .NET-documentatie staat nu online, is gratis en wordt bij elke nieuwe versie bijgewerkt.

    5.1.1. Online documentatie

    Het startpunt is de website learn.microsoft.com van Microsoft. Daar vindt u:

    • de documentatie van de taal C#: https://learn.microsoft.com/en-us/dotnet/csharp/. Deze bevat een overzicht van de taal, handleidingen, de taalreferentie (sleutelwoorden, operatoren, instructies) en een sectie „Wat is er nieuw” die elke versie van C# beschrijft;
    • de .NET API-referentie: https://learn.microsoft.com/en-us/dotnet/api/. Deze beschrijft, namespace voor namespace, alle klassen van .NET: hun constructors, eigenschappen en methoden, met voorbeelden;
    • de API-browser, op dezelfde pagina: een zoekvak waarin u de naam van een klasse of methode kunt typen ([StringBuilder], [Regex.Match]…). Met een keuzelijst kunt u de versie van .NET selecteren (hier .NET 10).

    De pagina van een klasse, zoals System.String, toont:

    • de namespace van de klasse en de assembly die haar bevat;
    • haar declaratie, bovenliggende klasse en de interfaces die zij implementeert;
    • een lijst van haar constructors, eigenschappen en methoden, elk met een link naar een gedetailleerde pagina met de verschillende overloads, parameters, retourwaarden, mogelijke uitzonderingen en vaak een voorbeeld;
    • opmerkingen over het gebruik.

    De pagina’s zijn beschikbaar in het Frans (machinevertaling) en in het Engels (oorspronkelijke tekst, die soms nauwkeuriger is). U kunt tussen beide wisselen door [en-us] te vervangen door [fr-fr] in de URL. Een zoekopdracht in een zoekmachine met de volledige naam van de klasse („System.Text.StringBuilder”) leidt meestal rechtstreeks naar de juiste pagina.

    5.1.2. Hulp in de editor

    De code-editor (Visual Studio, Visual Studio Code met de extensie C# Dev Kit, Rider) biedt directe hulp zonder dat u de code hoeft te verlaten:

    • automatisch aanvullen (IntelliSense): nadat u [aString.] hebt getypt, stelt de editor een lijst voor van de eigenschappen en methoden van het object, elk met een korte samenvatting;
    • Knopinfo: als u de muis boven de naam van een klasse, methode of variabele houdt, worden de declaratie en een samenvatting van de documentatie weergegeven;
    • Parameterhulp: wanneer u de openingshaak van een aanroep typt, toont de editor de verschillende overloads van de methode en de rol van elke parameter;
    • Naar definitie gaan (toets F12): toont de declaratie van de klasse of methode. Voor een .NET-klasse toont de editor de publieke declaraties die uit de assembly zijn gereconstrueerd, samen met hun documentatiecommentaar;
    • In Visual Studio opent u met de toets F1 op de naam van een klasse of methode de bijbehorende pagina in de online documentatie.

    Dit documentatiecommentaar, dat zichtbaar is wanneer u de muis boven een element houdt, wordt gebruikt om de online referentie te genereren. U kunt vergelijkbaar commentaar in uw eigen code schrijven met de syntaxis [/// <summary> ... </summary>] boven een klasse of methode: de editor toont het op dezelfde manier.

    // Split en Join
string line = "one:two::three:";
// opsplitsen met het scheidingsteken ':'
string[] fields = line.Split(':');
for (int i = 0; i < fields.Length; i++)
{
    Console.WriteLine($"fields[{i}]=[{fields[i]}]");
}
// de omgekeerde bewerking
Console.WriteLine($"join=[{string.Join(":", fields)}]");

// de opties van Split: lege velden verwijderen
fields = line.Split(':', StringSplitOptions.RemoveEmptyEntries);
Console.WriteLine($"RemoveEmptyEntries : {fields.Length} fields [{string.Join("|", fields)}]");

// meerdere scheidingstekens en de spaties rond de velden verwijderen
string person = " dupont , jean ;  45 ";
fields = person.Split([',', ';'], StringSplitOptions.TrimEntries);
Console.WriteLine($"TrimEntries : {fields.Length} fields [{string.Join("|", fields)}]");

// beide opties gecombineerd
string list = "  red ,, green ,  , blue ";
fields = list.Split(',', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
Console.WriteLine($"both options: {fields.Length} fields [{string.Join("|", fields)}]");

// een scheidingsteken dat een tekenreeks is
string text = "apple -> pear -> apricot";
fields = text.Split(" -> ");
Console.WriteLine($"string separator: [{string.Join("|", fields)}]");

// Join accepteert elke collectie, niet alleen tekenreeksen
int[] numbers = [1, 2, 3, 4];
Console.WriteLine($"Join on integers: {string.Join(" + ", numbers)}");

static double[] Input()
{
    // aan het begin is de array leeg
    double[] elements = [];
    // invoerlus voor de arrayelementen
    while (true)
    {
        Console.Write($"Element (real) {elements.Length} of the array (nothing to finish): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // einde van de invoer bij een lege tekenreeks
        if (answer == "")
        {
            break;
        }
        // controle van de invoer
        if (!double.TryParse(answer, out double element))
        {
            Console.WriteLine("Incorrect input, try again");
            continue;
        }
        // nog een element: we vergroten de array met één cel
        Array.Resize(ref elements, elements.Length + 1);
        // en we slaan het nieuwe element erin op
        elements[^1] = element;
    }
    return elements;
}

// in de array zoeken naar via het toetsenbord getypte elementen
static void Search(double[] elements, SearchType type)
{
    while (true)
    {
        Console.Write("Element searched for (nothing to stop): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // klaar?
        if (answer == "")
        {
            break;
        }
        // controle
        if (!double.TryParse(answer, out double element))
        {
            Console.WriteLine("Error, try again...");
            continue;
        }
        // we zoeken het element in de array
        int i = type == SearchType.Binary
            ? Array.BinarySearch(elements, element)    // gesorteerde array
            : Array.IndexOf(elements, element);        // willekeurige array
        // weergave van het antwoord
        Console.WriteLine(i >= 0 ? $"Found at position {i}" : $"Not in the array ({i})");
    }
}

    5.4. Generieke collecties

    Naast arrays zijn er diverse klassen om verzamelingen elementen op te slaan. Generieke collecties, geïntroduceerd met .NET 2.0, bevinden zich in de namespace [System.Collections.Generic], die deel uitmaakt van de impliciete [using]-namespaces. We introduceren eerst twee veelgebruikte collecties – de lijst en de dictionary – en behandelen daarna kort enkele andere.

    De namespace [System.Collections] bevat de oudere, niet-generieke versies van deze collecties, daterend uit .NET 1.0: [ArrayList] (een lijst), [Hashtable] (een dictionary)... De cursus van 2008 behandelde [ArrayList] nog. Deze klassen zijn nu verouderd: ze slaan referenties van het type [object] op, waardoor de gelezen elementen moeten worden gecast en getallen in objecten moeten worden verpakt (boxing), met bijbehorende geheugen- en tijdskosten. Generieke collecties hebben geen van deze nadelen: een *[List<int>] slaat zijn gehele getallen rechtstreeks op in een interne *[int[]] array, en de compiler controleert het type van de toegevoegde elementen. [ArrayList] en [Hashtable] mogen in nieuwe code niet meer worden gebruikt.

    5.4.1. De generieke klasse List<T>

    Met de klasse [System.Collections.Generic.List<T>] kunt u verzamelingen van objecten van het type [T] implementeren waarvan de grootte tijdens de uitvoering van het programma varieert. static void Search(List<double> elements, SearchType type)
{
    while (true)
    {
        Console.Write("Element searched for (nothing to stop): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // klaar?
        if (answer == "")
        {
            break;

            continue;

    De cursus van 2008 eindigde vlak vóór LINQ en introduceerde de anonieme typen ervan zonder ze daadwerkelijk te gebruiken.     • regel 31: [OrderByDescending] sorteert in aflopende volgorde; [ThenBy] (of [ThenByDescending]) voegt een secundair criterium toe, waarmee onderscheid wordt gemaakt tussen elementen die volgens het eerste criterium gelijk zijn: Durand en Laurent, die allebei 32 jaar oud zijn, worden op naam gesorteerd (regels 23–24);

    • queries kunnen kosteloos worden samengesteld: het aan elkaar schakelen van [Where], [Select] en [Take] maakt geen tussenliggende collectie aan, en alleen de noodzakelijke elementen worden berekend.

            output.Write(age);

    5.7.2. De JSON-serialisatie

    Een binair bestand byte voor byte schrijven en lezen is omslachtig, en zelfs de kleinste afwijking tussen schrijven en lezen levert onjuiste resultaten op. Het is over het algemeen beter om objecten te serialiseren: ze automatisch om te zetten in een reeks bytes of tekens en ze vervolgens te deserialiseren om ze te reconstrueren.

    .NET bood hiervoor de klasse [BinaryFormatter], die objecten serialiseerde naar een binair formaat dat specifiek is voor .NET. Die klasse is inmiddels verwijderd: ze werd in .NET 5 als verouderd aangemerkt en de implementatie ervan werd in .NET 9 verwijderd, omdat het deserialiseren van gegevens uit een onbetrouwbare bron met [BinaryFormatter] het uitvoeren van willekeurige code mogelijk maakte. Microsoft raadt aan de klasse te vervangen door de JSON-serialisatie van de bibliotheek [System.Text.Json], die sinds .NET Core 3.0 in .NET is geïntegreerd.

    JSON (JavaScript Object Notation) is een op tekst gebaseerd, voor mensen leesbaar en universeel formaat: het is het uitwisselingsformaat voor webservices (hoofdstuk 13) en talrijke configuratiebestanden. Een object wordt geschreven tussen accolades in de vorm van paren "eigenschap":waarde, met arrays tussen vierkante haken.

    5.8. Reguliere expressies

    De klasse [System.Text.RegularExpressions.Regex] ondersteunt het gebruik van reguliere expressies. Hiermee kunt u het formaat van een tekenreeks valideren. U kunt bijvoorbeeld controleren of een tekenreeks die een datum voorstelt inderdaad het formaat dd/mm/yy heeft. Daartoe gebruikt u een patroon en vergelijkt u de tekenreeks met dat patroon. In dit voorbeeld moeten d, m en y cijfers zijn. Het patroon voor een geldig datumformaat is dus [\d\d/\d\d/\d\d], waarbij het symbool [\d] een cijfer voorstelt. De symbolen die in een patroon kunnen worden gebruikt, zijn de volgende:

    teken
    beschrijving
    [\]
    markeert het volgende teken als speciaal teken of als letterlijk teken. Bijvoorbeeld: [n] komt overeen met het teken n, [\n] komt overeen met een regeleinde, [\\] komt overeen met \ en [\(] komt overeen met (
    [^]
    komt overeen met het begin van de tekenreeks
    [$]
    komt overeen met het einde van de tekenreeks
    [*]
    komt nul of meer keer overeen met het voorgaande element. [zo*] komt dus overeen met z of zoo
    [+]
    komt één of meer keer overeen met het voorgaande element. [zo+] komt dus overeen met "zoo", maar niet met "z"
    [?]
    komt nul of één keer overeen met het voorgaande element. Bijvoorbeeld: [a?ve?] komt overeen met “ve” in “lever”
    [.]
    komt overeen met elk afzonderlijk teken, behalve een regeleinde
    [(pattern)]
    zoekt het patroon en slaat de overeenkomst op (een groep). De overeenkomende subtekenreeks kunt u uit de verzameling [Groups] in het resultaat halen. Om overeenkomsten met tekens tussen haakjes te vinden, gebruikt u [\(] of [\)]
    [x|y]
    komt overeen met x of y. Bijvoorbeeld: [z|foot] komt overeen met z of foot; [(z|f)oo] komt overeen met zoo of foo
    [{n}]
    n is een niet-negatief geheel getal. Komt precies n keer overeen met het voorgaande element. Bijvoorbeeld: [o{2}] komt niet overeen met de o in Bob, maar wel met de eerste twee o’s in fooooot
    [{n,}]
    komt minstens n keer overeen met het voorgaande element. Bijvoorbeeld: [o{2,}] komt niet overeen met de 'o' in 'Bob', maar wel met alle 'o's in 'fooooot'. [o{1,}] is gelijkwaardig aan [o+], en [o{0,}] is gelijkwaardig aan [o*]
    [{n,m}]
    komt minstens n keer en hoogstens m keer overeen met het voorgaande element. Bijvoorbeeld: [o{1,3}] komt overeen met de eerste drie “o”s in “foooooot”; [o{0,1}] is gelijkwaardig aan [o?]
    [xyz]
    tekenverzameling: komt overeen met een van de opgegeven tekens. Bijvoorbeeld: [abc] komt overeen met de letter “a” in “plat”
    [^xyz]
    negatieve tekenverzameling: komt overeen met elk teken dat niet is opgesomd. Bijvoorbeeld: [^abc] komt overeen met "p" in "plat"
    [a-z]
    tekenbereik: komt overeen met elk teken in het opgegeven bereik, in dit geval een kleine letter zonder accent
    [^m-z]
    negatief tekenbereik: komt overeen met elk teken dat niet tussen 'm' en 'z' ligt
    [\b]
    komt overeen met een woordgrens, dat wil zeggen de positie tussen een woordteken en een niet-woordteken. Bijvoorbeeld: [er\b] komt overeen met "er" in "lever", maar niet met "er" in "verb"
    [\B]
    komt overeen met een positie die geen woordgrens is. [en*t\B] komt overeen met “ent” in “entertain”
    [\d]
    komt overeen met een cijfer; is gelijkwaardig aan [0-9] (in .NET ook voor cijfers uit andere Unicode-alfabetten)
    [\D]
    komt overeen met een teken dat geen cijfer is
    [\f], [\n], [\r], [\t], [\v]
    komen respectievelijk overeen met de tekens pagina-einde, nieuwe regel, regelterugloop, tab en verticale tab
    [\s]
    komt overeen met elk witruimteteken: spatie, tab, pagina-einde, regeleinde… Gelijkwaardig aan [ \f\n\r\t\v], plus andere Unicode-witruimtetekens (harde spatie, enz.)
    [\S]
    komt overeen met elk teken dat geen witruimteteken is
    [\w]
    komt overeen met elk woordteken: letter (met of zonder accenten), cijfer of underscore
    [\W]
    komt overeen met elk teken dat geen woordteken is
    [\num]
    num is een positief geheel getal: verwijst naar groepsnummer num. Bijvoorbeeld: [(.)\1] komt overeen met twee opeenvolgende identieke tekens
    [\xnn], [\unnnn]
    komt overeen met het hexadecimale teken nn (2 cijfers) of nnnn (4 cijfers). Bijvoorbeeld: [\x41] komt overeen met A

    Delen van een patroon kunnen worden “geëxtraheerd”. U kunt dus niet alleen controleren of een tekenreeks overeenkomt met een bepaald patroon, maar ook de elementen uit die tekenreeks halen die overeenkomen met de delen van het patroon die tussen haakjes staan.     In C#-code wordt een patroon bij voorkeur geschreven als verbatim string [@"..."]: zo hoeven de vele [\]-tekens in de patronen niet te worden verdubbeld. Met een gewone string zou u ***["\\\\d+"] moeten schrijven in plaats van ***[@"\\d+"].

    • regel 46: de tweede parameter van het attribuut is een combinatie van opties [RegexOptions]. [IgnoreCase] negeert hoofdletters en kleine letters: “YES” en “Yes” komen overeen met het patroon;
    • regel 17: de opties worden op dezelfde manier gebruikt met de methoden van [Regex]. Deze kunnen worden gecombineerd met de operator [|];
    • regel 50: het patroon [^(a+)+$] is pathologisch: bij toepassing op een reeks “a”s die eindigt met een ander teken probeert de engine voor reguliere expressies alle mogelijke manieren om de “a”s over de herhalingen van de groep te verdelen, voordat hij concludeert dat de zoekopdracht is mislukt. Het aantal mogelijkheden verdubbelt bij elke extra “a”: bij 30 “a”s zijn er ongeveer een miljard mogelijkheden. Dit staat bekend als catastrofaal backtracken. Een dergelijk patroon, toegepast op door gebruikers ingevoerde tekenreeksen, is een beveiligingslek: een paar verzoeken volstaan om een server te laten crashen. De parameter [matchTimeoutMilliseconds] stelt een timeout van 100 ms in: daarna wordt de zoekopdracht afgebroken met een uitzondering [RegexMatchTimeoutException] (regel 6);
    • regel 35: de optie [NonBacktracking] (.NET 7) gebruikt een andere engine, die een zoektijd garandeert die evenredig is met de lengte van de tekenreeks. Ze ondersteunt bepaalde constructies niet (bijvoorbeeld terugverwijzingen zoals [\1]), maar geeft in dat geval direct een resultaat.

    Houd er rekening mee dat u een timeout moet instellen of [NonBacktracking] moet gebruiken wanneer het patroon of de doorzochte tekenreeks van buiten het programma komt.

namespace TaxV3;

// de belastingschijven gelezen uit een tekstbestand met regels limit:coeffR:coeffN
public partial class FileTax : AbstractTax
{
    // het veldscheidingsteken: het teken : omgeven door optionele spaties
    [GeneratedRegex(@"\s*:\s*")]
    private static partial Regex Separator();

    // de uit het bestand gelezen belastingschijven
    private readonly TaxBracket[] taxBrackets;

    // implementatie van de abstracte property van de bovenliggende klasse
    protected override TaxBracket[] TaxBrackets => taxBrackets;

    public FileTax(string fileName)
    {
        // de naam van het bestand, zonder pad, voor de foutmeldingen
        string name = Path.GetFileName(fileName);
        // de gelezen schijven; we kennen hun aantal vooraf niet
        List<TaxBracket> brackets = [];
        try
        {
            int lineNumber = 0;
            foreach (string lineRead in File.ReadLines(fileName))
            {
                lineNumber++;
                string line = lineRead.Trim();
                // lege regels worden genegeerd
                if (line == "")
                {
                    continue;
                }
                // de regel moet drie velden hebben
                string[] fields = Separator().Split(line);
                if (fields.Length != 3)
                {
                    throw new TaxException($"Line no. {lineNumber} is incorrect ({line})")
                    {
                        Code = (int)ErrorCode.Line
                    };
                }
                // drie positieve decimale getallen of nul, geschreven met een decimale punt
                ErrorCode code = 0;
                if (!Read(fields[0], out decimal limit)) code |= ErrorCode.Field1;
                if (!Read(fields[1], out decimal coeffR)) code |= ErrorCode.Field2;
                if (!Read(fields[2], out decimal coeffN)) code |= ErrorCode.Field3;
                if (code != 0)
                {
                    throw new TaxException($"Line no. {lineNumber} is incorrect ({line})")
                    {
                        Code = (int)code
                    };
                }
                // we slaan de nieuwe belastingschijf op
                brackets.Add(new TaxBracket(limit, coeffR, coeffN));
            }
        }
        catch (Exception e) when (e is IOException or UnauthorizedAccessException)
        {
            // fout bij de toegang tot het bestand: we verpakken die in een TaxException
            throw new TaxException($"Error while reading the file {name}", e)
            {
                Code = (int)ErrorCode.Access
            };
        }
        // minstens één schijf is nodig
        if (brackets.Count == 0)
        {
            throw new TaxException($"The file {name} does not contain any bracket")
            {
                Code = (int)ErrorCode.Line
            };
        }
        // we zetten de lijst over in de array van schijven
        taxBrackets = brackets.ToArray();
    }

    // conversie van een veld naar een decimal >= 0, ongeacht de cultuur van de machine
    private static bool Read(string field, out decimal result) =>
        decimal.TryParse(field, NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture, out result);
}

            {

        try
        {
            // deserialisatie van de array van schijven
            brackets = JsonSerializer.Deserialize<TaxBracket[]>(json, options);
        }
        catch (JsonException e)

            throw new TaxException($"The file {name} is incorrect: {e.Message}", e)
            {
                Code = (int)ErrorCode.Json
            };

        if (brackets is null || brackets.Length == 0)

            throw new TaxException($"The file {name} does not contain any bracket")
            {
                Code = (int)ErrorCode.Json
            };
        }
        if (brackets.Any(t => t.Limit < 0 || t.CoeffR < 0 || t.CoeffN < 0))
        {
            throw new TaxException($"The file {name} contains a negative value")
            {
                Code = (int)ErrorCode.Json
            };
        }
        taxBrackets = brackets;
    }

    using TaxV3;

// belastingberekening, versie 3: de belastingschijven worden uit een bestand gelezen
// syntaxis: dotnet run [-- file]; file: standaard TaxData.txt, of een .json-bestand

const string syntax = """
    syntax: Married NbChildren Salary
    Married: y for married, n for not married
    NbChildren: number of children
    Salary: annual salary in euros
    """;

// het gegevensbestand wordt naast het uitvoerbare bestand gezocht
string fileName = args.Length > 0 ? args[0] : "TaxData.txt";
string path = Path.Combine(AppContext.BaseDirectory, fileName);
Console.WriteLine($"Tax brackets read from [{fileName}]");

// aanmaken van een ITax-object; de klasse hangt af van de extensie van het bestand
ITax tax;
try
{
    tax = Path.GetExtension(fileName).ToLower() switch
    {
        ".json" => new JsonTax(path),
        _ => new FileTax(path)
    };
}
catch (TaxException e)
{
    // weergave van de fout; de code wordt weergegeven als een combinatie van ErrorCode
    string origin = e.InnerException is null ? "" : $", original exception: {e.InnerException.GetType().Name}";
    Console.WriteLine($"The following error occurred: [Code={(ErrorCode)e.Code}, Message={e.Message}{origin}]");
    // het programma stoppen
    return 1;
}

// invoerlus
while (true)
{
    // we vragen om de parameters voor de belastingberekening
    Console.Write("Tax calculation parameters in the format: Married (y/n) NbChildren Salary, or nothing to stop: ");
    string parameters = (Console.ReadLine() ?? "").Trim();
    // is er iets te doen?
    if (parameters == "")
    {
        break;
    }
    // controle van het aantal velden van de getypte regel
    string[] fields = parameters.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    if (fields.Length != 3)
    {
        Console.WriteLine(syntax);
        continue;
    }
    // controle van de geldigheid van de parameters
    // married
    string married = fields[0].ToLower();
    if (married != "y" && married != "n")
    {
        Console.WriteLine(syntax + "\nIncorrect married argument: type y or n");
        continue;
    }
    // nbChildren
    if (!int.TryParse(fields[1], out int nbChildren) || nbChildren < 0)
    {
        Console.WriteLine(syntax + "\nIncorrect NbChildren argument: type a positive or zero integer");
        continue;
    }
    // salary
    if (!int.TryParse(fields[2], out int salary) || salary < 0)
    {
        Console.WriteLine(syntax + "\nIncorrect salary argument: type a positive or zero integer");
        continue;
    }
    // de parameters zijn correct: we berekenen de belasting
    Console.WriteLine($"Tax={tax.Calculate(married == "y", nbChildren, salary)} euros");
}
return 0;

    • regel 14: de naam van het gegevensbestand wordt als argument doorgegeven; standaard is dat [TaxData.txt];
    • regel 15: het bestand wordt gezocht in de map van het uitvoerbare bestand, [AppContext.BaseDirectory], waarheen het tijdens het compileren is gekopieerd. Het programma vindt zijn gegevens dus ongeacht de map van waaruit het wordt gestart, wat niet gold voor de toepassingen met één bestand in dit hoofdstuk;
    • regels 22–25: een [switch] -expressie (hoofdstuk 3) selecteert op basis van de bestandsextensie de klasse die moet worden geïnstantieerd. De twee takken geven verschillende typen terug, [JsonTax] en [FileTax]: de compiler leidt het type van de expressie af uit de doelvariabele [tax], die van het type [ITax] is ([switch] -expressie met doeltype). De rest van het programma kent alleen de interface [ITax] en weet niet waar de gegevens vandaan komen;

    5.10. Conclusie

    In dit hoofdstuk zijn de .NET-klassen geïntroduceerd die in vrijwel alle programma’s worden gebruikt:

    • onveranderlijke tekenreeksen ([string]) en veranderlijke tekenreeksen ([StringBuilder]) om ze stukje voor stukje op te bouwen; interpolatie met breedtes en formaten, onbewerkte tekenreeksen (raw strings); weergaven ([ReadOnlySpan<char>]) voor kritieke code;
    • de arrays en de klasse [Array];
    • generieke verzamelingen [List<T>], [Dictionary<TKey,TValue>], [HashSet<T>], [Queue<T>], [Stack<T>], [PriorityQueue<TElement,TPriority>] en hun alleen-lezen interfaces; de niet-generieke verzamelingen [ArrayList] en [Hashtable] zijn verouderd;
    • LINQ, de sequenties [IEnumerable<T>] ervan, de iterators en de uitgestelde uitvoering;
    • tekstbestanden ([StreamReader], [StreamWriter], [File]), binaire bestanden ([BinaryWriter], [BinaryReader]) en de JSON-serialisatie, die de binaire serialisatie van [BinaryFormatter] vervangt, dat uit .NET is verwijderd;
    • reguliere expressies, bij voorkeur gegenereerd tijdens het compileren en altijd beveiligd met een timeout bij de verwerking van externe gegevens.

    De voorbeeldapplicatie leest haar gegevens nu uit een tekstbestand of uit JSON. In het volgende hoofdstuk wordt ze herorganiseerd in lagen: het lezen van gegevens, het berekenen van belasting en de gebruikersinteractie worden onafhankelijke componenten.
